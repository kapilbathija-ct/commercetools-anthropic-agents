# Sequence diagrams

Six diagrams of the same three flows, drawn from the real traces in `WALKTHROUGH.md` rather
than from design intent — so the round counts and the call order are what the code does.

## Two sets, for two audiences

**Four-lane** — browser, agent, commercetools, Anthropic. What the agent does internally is
a self-arrow or a note, so the four boundaries that matter stay readable. Use these with
anyone who is not going to read the code.

**Eight-lane** — the agent split into route, orchestrator, executor, backend and mapper. Use
these with an engineer who wants to know which file owns which step.

## The files

| Flow | Four-lane | Eight-lane |
|---|---|---|
| Shopping — "chairs under $1000" | `simple-1-shopping` | `1-shopping-path` |
| Merchant read — slow sellers | `simple-2-merchant-read` | `2-merchant-read-path` |
| Merchant write — the approval gate | `simple-3-merchant-write` | `3-merchant-write-path` |

All under `docs/diagrams/`, each as `.mmd` (the source) and `.png` (a render).

## Editing them

**In draw.io**, open `docs/diagrams/sequence-diagrams.drawio` — three tabs of native shapes,
generated by `scripts/make_drawio.py` from the flows declared as data in that script. draw.io
also imports Mermaid directly: Arrange → Insert → Advanced → Mermaid, pasted from a `.mmd`.

**As Mermaid**, edit the `.mmd` and re-render. A `;` inside message text is a statement
separator and will break the parse — the reason diagram 2 silently failed the first time.
Note that a failed render and an absent renderer look identical, so check in something you
know renders, not only in an editor preview.
